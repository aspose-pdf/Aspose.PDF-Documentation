## Настройка среды

Наша установка состоит из 4 серверов. Он включает в себя контроллер домена, SQL-сервер, сервер SharePoint и сервер служб отчетов. Вы можете разместить SharePoint и Reporting Services на одном компьютере, что немного упростит задачу, и я укажу на некоторые различия.

## Предварительные требования к установке

{{% alert color="primary" %}}

Надстройка служб Reporting Services для SharePoint — один из ключевых компонентов для правильной работы интеграции. Надстройку необходимо установить на любом интерфейсном веб-интерфейсе (WFE), который находится в вашей ферме SharePoint вместе с сервером центрального администрирования. Одним из новых изменений в SQL 2008 R2 и SharePoint 2010 является то, что надстройка 2008 R2 теперь является обязательным условием для установки SharePoint. Это означает, что надстройка RS будет установлена, когда вы приступите к установке SharePoint. Это было показано и выделено на рисунке ниже. Это фактически позволяет избежать многих проблем, которые мы наблюдали в SP 2007 и RS 2008 при установке надстройки.

ПРИМЕЧАНИЕ. ***Reporting Services 2008 R2 НЕ поддерживает утверждения***

Даже если вы выберете на своем сайте SharePoint использование утверждений, службы Reporting Services сами по себе не поддерживают утверждения. Тем не менее, это влияет на работу проверки подлинности в службах Reporting Services. Итак, в чем же разница с точки зрения служб Reporting Services? Все сводится к тому, хотите ли вы пересылать учетные данные пользователя в источник данных. Классический: — Можно использовать Kerberos и пересылать учетные данные пользователя в внутренний источник данных (для этого необходимо будет использовать Kerberos). Утверждения: — используется токен утверждений, а не токен Windows. В этом сценарии RS всегда будет использовать доверенную аутентификацию и будет иметь доступ только к токену SPUser. Вам нужно будет хранить свои учетные данные в источнике данных.

Классический: — Можно использовать Kerberos и пересылать учетные данные пользователя на внутренний источник данных (для этого необходимо будет использовать Kerberos).

Утверждения: — используется токен утверждений, а не токен Windows. В этом сценарии RS всегда будет использовать доверенную аутентификацию и будет иметь доступ только к токену SPUser. Вам нужно будет хранить свои учетные данные в источнике данных.
